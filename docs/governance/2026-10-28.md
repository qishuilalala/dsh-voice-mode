## Dependabot 更新与安装验证链修复

- 根因一：npm 更新没有分组；多条独立 PR 同时改写同一锁文件及 peer 解析，先合并后其余出现冲突。新增常规 minor/patch 组；两个 Sherpa 包按原生运行时成组，esbuild 单独成组，Actions 更新成组。其他大版本仍独立审查；分组不等于自动合并，不屏蔽安全更新。
- 根因二：安装 job 使用非锁定的 npm 安装，并打包 Git 中已有的 lib；test job 的新构建没有进入该安装 job。修复为 Node 22 下 frozen 安装并构建，再切到 Node 18/22 验证新产物的安装与入口加载。
- 隔离反向验证：旧 lib 的内联合成模块临时加入 STALE_ARTIFACT_REPRO 标记，运行既有安装脚本，两种安装器均在加载时失败；恢复并用 esbuild 0.28.2 构建后，两种安装均通过。临时注入未提交。
- 本轮升级 esbuild 至 0.28.2，同时协调 host-webserver rc.3 和 Node 类型补丁。检查 npm tarball 得出宿主包代码/声明未变，但元数据固定了 Cordis/Schemastery；更新锁文件保留无关解析。
- 上游构建要求变化：[esbuild 0.27.0](https://github.com/evanw/esbuild/releases/tag/v0.27.0) 提高 macOS 构建环境至 12；[0.28.0](https://github.com/evanw/esbuild/releases/tag/v0.28.0) 增加备用下载摘要检查。开发说明同步；运行时 Node 下限不随构建器升级改变。
- 分组行为依据：[GitHub Dependabot 配置](https://docs.github.com/en/code-security/reference/supply-chain-security/dependabot-options-reference#groups)。常规组只用于 version updates，安全更新保持独立；未设置忽略规则或自动合并。
- 本地验证：新编译器构建、npm/pnpm 全新安装与入口加载成功；最终是否合并以 PR #41 最新提交的完整 CI 为准。macOS 未实机验证，不据此宣称跨平台已验收；本轮没有 npm 发布。
