4. 历史 2026-09-14-fixture-verdict 的四条录音只有两次打断事件。其漏检率及 p95 讨论应作为待复核的证据强度问题；不能把相关音频帧当成独立试验。单一 crest 特征重叠也不证明所有信号特征或方法都不可区分。此处不宣布当前实现有缺陷或撤销已接受 ADR。

先声明你观察到的 Git commit、npm 版本、硬件、OS、宿主/浏览器版本、网络与运行形态。不要沿用交接中的版本号作为事实。读取当前源码前按当地规则使用 CodeGraph，之后以实际源码与日志校验图谱结果。记录生产分支、实验分支和 npm 产物差异。

构造因果链：采集→AEC/VAD→分段/流式→定稿/可选纠错→草稿与手改→提交→宿主任务→合成→客户端实际播放。标明线程/进程、队列、状态所有者、会话与代际、取消、重试、数据去向。区分系统观测时刻与真实物理时刻；跨进程/设备时钟未校准不得相减得出精确延迟。

四、模型与免费在线语音的研究深度

检查代码许可、权重/音色/数据许可，原始与转换模型来源、不可变 revision、所有依赖资产、运行时/ABI、CPU/RAM/下载/冷暖启动、语言与代码标识符、取消和真实播放方式。不能从 Python demo 成功推出 Node/Electron 可维护；也不能把当前接口限制当作永不可改变的事实。若新架构有显著机会，可隔离 PoC，但必须核算控制、可审阅文本、取消、成本与宿主集成的损失。

五、最小但有区分力的实验

优先复用现有 recorder、分析脚本和回归装置，不先建设评测平台。按证据需求选用：NIST SCTK 做固定归一化的 CER/WER；Python 做逐任务配对比较和区间估计；浏览器 Performance/Web Audio 时间线定位；FFmpeg/ffprobe 检查音频；必要时外部录音或声卡回环测真实首音与停声；浏览器自动化重放草稿时序；隔离网络环境注入延迟、断网、乱序和取消。仅当现有路径实际使用 RTCPeerConnection 时才考虑 WebRTC 专属统计，不能硬套。

固定文本与切分策略，保留数字/否定词/代码标识符等语义关键错误，防止归一化抹掉损失。真实说话人、设备、会话分层，不能把同一条录音的帧当独立样本。探索集与最终验证集分开，固定参数后再验证。顺序随机/平衡，保留失败和退出者。样本数由可用资源、独立单位、目标精度/差异决定；小样本只作试点，不靠重复播放伪造有效样本量。p95 报样本量、估计方法与不确定性；零次失败也要报告暴露量，不能宣布零风险。

TTS 做随机编号、响度受控的配对盲听，按 ITU 方法理解筛查与评价条件；自然度、可懂度、长时间听取和任务完成分开。没有真人不能写真人听感通过；合成输入和虚拟麦克风不能代替真实声学/AEC 测试。

每个实验事先记录主要判据、不可劣化约束、预期反例、停止规则。阈值必须有用户容忍度、基线或明确政策依据；不要默认沿用旧路线的 20%/10%。安全、数据去向和收费授权不能被加权收益抵消。若资源不足以决定，给出下一项最有信息量且最便宜的实验，而非强行推荐。

七、形成决策与可审查交付

最多交付三个主决策，每个用同一结构：

只在此后写简短的条件路线：若证据 A 成立做 X，否则保留/做 Y；没有证据先做 Z 实验。不要先给季度排期或用大阶段代替决策，不预设必须新增模型或后端。已确认缺陷另列修复任务，写复现、最小改动、回归与真实验收；本轮不越权修改生产。

交付目录必须包含：
1. REPORT.md：结论、三个决策及条件路线。
2. EVIDENCE.csv：claim_id、事实/假设/推论、证据级别、来源与时间/版本、原始工件、支持边界、反证与关联决策。

5. REVIEW.md：按 Blocker / Important / Minor / Open Questions / Verdict 进行反方审查，重点尝试推翻最强建议。

最后给接收审查者一页交接：三项最重要发现、确认缺陷、未验证依赖、改变了哪些原有判断、三条优先复跑命令、文件白名单。至少有一条检查能在故意引入错误或旧行为时失败；说明它验证哪条主张以及不验证什么。不能安排真人或第二设备就明确登记，不能用另一位 AI 同意代替。
