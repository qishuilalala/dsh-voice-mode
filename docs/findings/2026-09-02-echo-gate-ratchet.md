# 发现：回声地板棘轮机制存在，但真机上不发作；门控之所以无效是「从未被查询到」

- 日期：2026-09-02（**当日经真机 fixture 修订，结论已推翻初版**）
- 状态：**已用真机数据判定**
- 证据：两条真机录制（`build=04b5973`，外放，原生 AEC 生效），共 3.1 分钟朗读期
- 复现：`node scripts/bench-echo-gate.mjs`（合成）｜`node scripts/analyze-fixture.mjs <fixture>`（真机）

---

## 修订说明（必读）

本文初版（同日早些时候）宣称："回声门控在真实回声下判别力≈0，门 99.8% 帧打开"。
**该结论被真机数据推翻。** 初版的错误与更正如下：

| 初版说法 | 真机实测 | 判定 |
|---|---|---|
| 纯回声期门开率 99.8% | **0.3%**（①）/ **27.1%**（②） | ❌ 严重高估 |
| 地板冻结率 85–97% | **0.3%** / **16.4%** | ❌ 严重高估 |
| 地板低估真实回声 28–57 dB | **0.1 dB** / **2.8 dB** | ❌ 严重高估 |
| 判别余量 ≈0.4pt | 门控未被触及，无从比较 | ❌ 前提不成立 |
| 判据：crest（max/mean）≥7dB ⇒ 保留语音包络 | 真机 crest 8.6/12.4dB 却不发作 | ❌ **判据本身选错** |
| （二改）中位/均值 ≥0.75 ⇒ 不发作 | 合成 1.07 冻结 85%，真机 1.00 冻结 0.3% | ❌ **也不成立，已撤销** |

**根因**：我用来预测的合成残差比真实残差"尖"得多。WebRTC AEC3 的 RES 把残差整形成了噪声，
这一点 ADR-0001 里其实写了（"52ms 线性 + 残差回声抑制 RES"），我建合成信号时没把它建进去。

**更重要的是：不存在能预测棘轮强度的简单统计量。** 我先后试过 crest、中位/均值、p90/中位、
调制周期，全部不单调：

| 信号 | 中位/均值 | p90/中位 | 冻结率 |
|---|---|---|---|
| 合成 gap=1 | 1.07 | 1.92 | **85.5%** |
| 真机① 纯听 | 1.00 | 1.37 | **0.3%** |
| 真机② 打断 | 0.80 | 2.62 | **16.4%** |

原因是棘轮是**双稳态动态**：地板一旦开始塌就正反馈继续塌，落在哪个稳态取决于初期越过
`floor×2` 的帧够不够多——这是轨迹依赖的，不是分布形状的函数。

所以正确做法不是找代理量，而是**直接读引擎每帧记下的真值**（`dt` / `fl` / `pk`）。
录制器本来就记了这三列，`analyze-fixture.mjs` 已改成只报真值、不再给分布判据。

## 仍然成立的部分：机制本身是真的

代码层面的推理没有问题：

```
gateRatio  = 10^(echoGateDb/20)                                  asr.ts:575
doubleTalk = playing && floor > 0 && rms > floor * gateRatio      asr.ts:588
地板仅在 !doubleTalk 时更新（EMA）                                 asr.ts:591
peak       = max(peak * 0.9^(d/64), rms)   ← 峰值保持              asr.ts:583
门开       = peak > floor * gateRatio                             asr.ts:849-852
```

响于 `floor × gateRatio` 的帧一律被排除在地板更新之外 ⇒ 地板只能被安静帧拉低 ⇒
残差越"尖"，地板越往音节间隙塌。这是单向棘轮，**是代码的直接推论，不依赖任何假设**。

三个实测点（引擎真值，非重放）：

| 录制 | doubleTalk 触发率 | 门开率 | 地板低估残差均值 |
|---|---|---|---|
| ① 纯听（124.6s） | 0.3% | 0.3% | 0.1 dB |
| ② 打断（61.8s） | 16.4% | 27.1% | 2.8 dB |
| 合成压力档 | 97.4% | 99.8% | 57.1 dB |

原生 AEC 生效时棘轮几乎不动，但**并非没有咬**：①→② 之间冻结率翻了 50 倍。
两个稳态之间的边界在哪、什么条件会跨过去，**目前不知道**——只知道它是轨迹依赖的，
不能从残差的分布形状推出来。

原生 AEC 失效（耳机无 AEC / Safari）时走自研 NLMS 路径，**那一格还没有任何数据**，
是本条留下的真实风险。

## 真正的结论：门控从未被查询到

真机数据里最关键的一列，是初版完全没有的：

| 录制 | 朗读期 Silero 有回报的帧 | 其中 `isSpeech=true` |
|---|---|---|
| ① 纯听 | 505 | **0** |
| ② 打断 | 272 | **0** |
| 合计 | **777** | **0（0.0%）** |

Silero 在 3.1 分钟朗读期里，**一帧都没有把回声判成语音**。

打断的必要条件是 `isSpeech` 连续 `confirmFrames` 次为真（`client.tsx:1386-1390`），
回声门控只在计数达标之后才被查询（`:1393`）。计数从未达标 ⇒ **门控这一道代码从未执行过**。

所以初版那句"`echoGateDb` 在常见场景下接近空操作"**结论恰好是对的，但理由完全错了**：
不是"走到了但判不出来"，而是"根本没走到"。

真正在拦自打断的是 **Silero VAD 对被原生 AEC 压低的残差不判语音**——这正是 ADR-0001
的决策在起作用。ADR-0001 是对的，而且比它自己声称的还管用。

## 这对决策意味着什么

### ADR-0001（原生 AEC 为主）
**被真机数据加强**。残差均值 0.0011（①）/ 0.0008（②），比同一录制里的非播放期底噪
（0.0056 / 0.0029）还低 5 倍——原生 AEC 把回声压到了环境噪声之下。自研 NLMS 全程旁路。

### ADR-0006（打断模式自动探测降级）
我此前据初版把"用 `echoFloorRms` 当回声电平估计"判为作废，**这个否决要撤回**：
真机上地板对残差均值的误差只有 0.1 / 2.8 dB，是可用的估计量。

但仍需保留一个约束：**误差随残差尖锐度上升**（0.1 dB → 2.8 dB 已经翻了 28 倍）。
第二级探测若用地板，应同时记录 doubleTalk 触发率作为置信度——触发率高时地板不可信，
改用播放期残差中位数。

### `echoGateDb` 与 README
结论不变：这个旋钮在当前主流路径上不起作用（因为没走到），README 的排障建议应当改掉。
但措辞要改——不能说"它判错了"，要说"它没被触发到；打不断的原因在 VAD 或延迟，不在这个阈值"。

### 合成基准 `bench-echo-gate.mjs`
它**不是**真机预测器，只是棘轮机制的压力测试。已做的调整：
1. 文件头与报告里明确标注"这是机制上界，不是现状"，并附真机实测对照
2. 明确写出"合成档与真机之间没有可用的映射关系，要知道真机什么样只能录一条"
3. 保留尖锐档——它守的是"原生 AEC 失效"那条尚无数据的路径

**不做**"按真机标定一档"：既然没有能对齐两者的统计量，标定出来的也只是看起来像。

## 方法论教训（值得记下来）

1. **合成信号必须先用真机数据标定，否则它证明的是自己的假设。** 我把语音包络直接当成
   AEC 残差的包络，跳过了 RES 这一环——而 RES 的全部作用就是消除这个包络。
2. **代理指标要先证明它能预测，再拿来用。** 我连续找了四个代理量（crest、中位/均值、
   p90/中位、调制周期），每一个在合成数据上看着都成立，一对真机就散架——因为目标量
   （棘轮强度）是轨迹依赖的双稳态，本就不是分布的函数。**当被测系统自己就能记录真值时，
   不要用代理量。** 录制器记 `dt`/`fl`/`pk` 三列的成本是每帧 3 个数字，而它让所有代理量都变得多余。
3. **埋点要覆盖"上游是否放行"，不只是"本环节判得对不对"。** 初版分析了门控的判别力，
   却没问"门控会被执行吗"。`spk` 这一列是靠真机录制才补上的，它一到手，结论就翻了。
