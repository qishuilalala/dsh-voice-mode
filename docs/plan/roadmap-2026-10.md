# 后续路线图：可持续更新的语音工作流（2026-10-28）

> 状态：路线提案；已确认缺陷按独立修复处理，候选能力不代表已实现或已批准改变默认值。调研时点为 2026-10-28，模型、价格与条款在接入前重查。
> 当前工程基线：已合并治理 PR #31 与 Kokoro int8 修复 PR #32；fp32/支持文件补修 PR #33 也已通过五项检查并合并。未发布的代码不能当成 npm 用户已获得的修复。
> 本文是当前路线的优先级入口；旧竞品 backlog 保留历史证据，不再把其中的 Ready 或工期当作当前交付承诺。

## 1. 第一性原理：先定义值得优化的结果

项目的工作是把人的表达可靠地变成可控的宿主输入，并把回复变成可听、可打断、可继续阅读的信息。模型只是其中一个部件。

最小成功链：开麦 → 保留用户表达 → 可编辑草稿 → 按用户设置发送 → 宿主回复 → 可选朗读 → 可中断并恢复到明确状态。

总体验成本包括等待、修正错误、判断当前状态、故障恢复、隐私暴露、硬件与维护成本。模型榜单只覆盖其中一部分；字错率更低但误发更多、冷启动更慢或无法取消的方案，可能更差。

先采用以下产品假设，后续用观察修正：

- 首要用户是在 dsh 内进行中文及中英混合任务的个人开发者；浏览器和官方桌面端是使用边界，不做全系统输入法。
- 优先支持无 GPU、无需额外语音 API 账号的基本路径；有 GPU 或付费账户属于可选增强。
- 用户应能选择按住说话、审阅后发送或现有自动发送；不以自然对话演示为理由取消明确控制。
- 本地 ASR/TTS 不等于整个对话离线；宿主 LLM 仍可能访问网络。
- 任何扩展都必须保住：不静默丢句、不把引用内容当命令、不覆盖用户编辑、不在取消后重试播放、不暗中改变数据去向。

这些是本路线的设计假设，不是已经完成用户调研的结论。长文本听写、免手操作、自然对话三类任务的优先级，需在真实任务评估中再次排序。

## 2. 当前事实、故障与证据边界

| 项目 | 已有证据 | 不能由此推导 |
| --- | --- | --- |
| Edge | 现有内联发布产物实时合成 11232 字节 | 永久免费、稳定 SLA、所有地区可达、真人听感通过 |
| VITS | 当前 Linux 缓存、禁止下载，生成 73118 字节 WAV | 全新安装/所有平台/麦克风端到端通过 |
| Kokoro int8 | 历史版本修复后真实合成；禁网复测 125786 字节、约 14.1 秒 | 流式低延迟或交互级实时性；该时间不是首音 p95 |
| Kokoro fp32/中文词典 | 当前 main 摘要与固定值失配，历史提交匹配；补修及回归已通过 CI 并合并，未发布 | fp32 模型已下载或真实推理/听感通过 |
| 工程门禁 | PR #31、#32 五项检查成功；源码、产物与文档有独立验证 | 测试数、扫描分数等同用户任务质量 |
| 辅助目录 | 当前用目录清单/存在性等检查，未逐文件固定摘要 | 已完成全模型资产锁定 |

缺陷处置纪律：先给出输入/时序、当前源码位置和后果，复现后修复；发现风险不自动宣布存在漏洞。真实音频工件不默认提交公开仓库。详细记录见[现有治理报告](../governance/2026-10-28.md)。

已确认并需闭环的问题：

1. 上游 main 替换模型/词典，导致首次下载永远无法满足固定摘要。int8、fp32 与支持文件补修均已合并；后续发布与安装验证仍需闭环。
2. 先前恢复点“CI 尚未执行”等状态过期：同步为当前 PR/检查结果，不把历史段落当现行命令。
3. 旧传输提案暗示 WebSocket 有序即可消除异步代际守卫，此推论不成立：任务取消、跨连接恢复、模型/LLM 的并发完成仍需要生命周期校验。纠正提案说明，不因此实施协议迁移。
4. 真实 ASR、麦克风与听感未验收：补证据，不用合成音频非零或 mock E2E 替代真人场景。

## 3. “免费语音”必须按服务契约分层

| 类型 | 可用价值 | 必须显式说明的代价 | 本项目取舍 |
| --- | --- | --- | --- |
| Edge 等免密钥在线客户端协议 | 零账号设置、音色便利 | 接口会变化；本轮未取得正式 API/SLA 与授权范围保证；文本离开本机 | 保留便利路径，配真实探针、可见错误和用户批准的退路；不宣传无限可靠 |
| 官方云 API 的免费额度 | 接口/额度/限流有正式文档 | 账号、地域、计费、超额与凭据管理；有的要求启用 billing | 有需求时只评估一个自带凭据候选，零新增后端也是有效结论 |
| 本地模型 | 无逐次服务费、可离线推理 | 模型许可、下载、磁盘、冷启动、CPU/RAM、电量、原生分发 | 先证明当前模型在目标机器上可用，再竞争性评估替换 |
| 客户端系统/浏览器语音 | 可能无需额外下载大模型 | 音色/语言/离线性随客户端变化；服务器声音不是用户设备声音 | 小型 PoC；不得假设能返回与当前引擎相同的音频字节 |
| 在线 demo、Spaces、公共体验站 | 研究质量、人工试听 | 无稳定服务承诺、可能排队/休眠、条款和隐私不清楚 | 仅研究，不当生产后端，不做免费站点抓取聚合 |

官方资料支持的边界：Edge 客户端项目说明无 API Key 的在线调用；这不是微软 SLA 的证据。[edge-tts](https://github.com/rany2/edge-tts)

Azure 免费层有配额与速率限制；接入时重查具体区域和音色，不在本路线写死永久额度。[Azure 配额](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/speech-services-quotas-and-limits)

Google Cloud TTS 要求开启 billing，超出免费字符后计费，且部分音色家族没有免费额度。必须先取得用户费用授权，不能把“存在免费层”当作“不会收费”。[官方定价](https://cloud.google.com/text-to-speech/pricing)

浏览器的 localService 只说明该声音由本地还是远程服务提供，跨设备可用性与实际断网行为仍须测试。[MDN](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisVoice/localService)

## 4. 模型候选池：只研究能改变结果的选项

不按发布日期或宣传榜单直接更换默认模型。每轮最多两名挑战者与现有基线对比，未通过就保留现状。

| 能力 | 当前基线 | 候选与借鉴价值 | 进入实验的前提/淘汰条件 |
| --- | --- | --- | --- |
| 流式识别 | sherpa/zipformer | sherpa 可用的其他流式模型；FunASR 的流式工具链 | 中文/混说与打断录音上更少修正；CPU 与打包负担在预算内，否则淘汰 |
| 定稿识别 | SenseVoice | Qwen3-ASR、whisper.cpp 及更新的 SenseVoice 导出 | 相同语料、硬件、分段策略对比；不会流式的模型只能先做定稿候选，不假装零成本替代流式链 |
| 本地朗读 | VITS/Kokoro | CosyVoice 等更具表达力的候选；同运行时其他轻量模型 | 音质收益必须超过冷启动、内存与安装负担；需大型 GPU 服务的方案先放可选外部服务实验 |
| 低负担朗读退路 | 现有手动切换本地引擎 | 浏览器/系统语音 | 客户端取消与可用性可验证；不能满足音频字节接口则单独评估播放路径，不强塞进现有接口 |
| 轮次结束与打断 | 服务端 Silero、现有端点及 AEC | 语义轮次检测、客户端 VAD 小 PoC | 只有误切句/打断延迟证据指向该环节才启动；必须同时测误打断和漏打断 |
| 正式在线合成 | Edge 便利路径 | 一个用户自带凭据的官方 API 候选 | 用户确有音色、可用性或合规需求；先测费用上限、限流和取消，不能只看合成成功 |

来源与许可复核入口：

- [sherpa-onnx 官方文档](https://k2-fsa.github.io/sherpa/onnx/index.html)：部署运行时与模型兼容入口；代码支持某模型不等于本插件当前包支持它。
- [SenseVoice](https://github.com/QwenAudio/SenseVoice)、[模型卡](https://huggingface.co/FunAudioLLM/SenseVoiceSmall)、[FunASR](https://github.com/modelscope/FunASR)：分别核对模型权重、工具链与导出格式。代码许可不代替权重/音色许可。
- [Qwen3-ASR](https://github.com/QwenLM/Qwen3-ASR)、[whisper.cpp](https://github.com/ggml-org/whisper.cpp)：候选能力来源，未在本机比较质量或性能。
- [Kokoro 模型卡](https://huggingface.co/hexgrad/Kokoro-82M)、[CosyVoice](https://github.com/QwenAudio/CosyVoice)：上游模型与当前 ONNX 转换物分别审核。
- [Piper 当前项目](https://github.com/OHF-Voice/piper1-gpl)：当前代码标明 GPL-3.0；不能照搬旧 fork 的许可假设，也不能凭进程隔离自行宣布不存在分发义务。暂不直接内联。

不新增通用插件市场、全能 provider registry 或任意脚本执行接口。现有 [TtsEngine](../../plugin/dsh-voice-mode/src/tts-queue.ts) 已承担字节合成、取消与关闭；只有第二个真实后端暴露出共同需求后，才改变接口。真正流式音频需要独立协议与取消测试，不能把一次性 Buffer 包装成“流式”宣传。

## 5. 竞品借鉴：转化为可验证机制

| 产品/领域 | 官方资料中的机制 | 对本项目的建议 | 反例与不照搬的边界 |
| --- | --- | --- | --- |
| Wispr Flow | 上下文感知；听写与 Command Mode 有不同入口及取消 | 优先保住草稿，重写可审阅/撤销；未来命令能力必须明确意图与授权 | 读取上下文会增加隐私面；先限用户当前输入/选区，不默认读全屏或其他应用 |

| VS Code | 展示差异、选择应用/撤回、冲突时比较 | 定稿晚到与手工编辑冲突时保留用户修改，提供候选而非覆盖 | 不为一句短听写强制弹复杂 diff；只在冲突或明显重写时展示 |

| Linear | intake/triage 和明确状态 | 区分“听见/识别中/草稿已保存/等待发送/发送失败”，按影响分流反馈 | 不把每个内部 RPC 都变成产品状态，也不新增任务管理系统 |

## 6. 评估标准：先建立基线，再决定阈值

先固定五个主指标，其余数据只作定位：

1. 任务完成率：用户本来要发送/编辑的内容最终是否正确到达宿主；区分主动取消和系统失败。
2. 误发/丢句：错误发送、重复发送、漏头尾、跨会话串音、取消后复活；关键故障有限测试集必须零复现。
3. 修正成本：每任务手工修正次数、修正耗时；ASR 字错率下降但误改语义上升不能算胜出。
4. 首音与打断 p50/p95：分别从用户停止说话到实际首个可听帧、从用户有效打断到扬声器停止。把等待 LLM、下载与本地合成拆开诊断。
5. 可用性：冷安装、暖启动、断网、缺模型情况下，成功/可恢复失败/无法恢复失败分别计数。

台架必须记录：硬件/内存、OS/架构、浏览器或 Electron 版本、模型 revision+摘要、音色、网络条件、冷暖状态、语料和分段策略。不同测试机的值不直接混为同一 p95。

首轮用小而真实的任务集跑通闭环：中文代码标识符、中英混说、长句停顿、修正前一句、静音/噪声、朗读时打断。补三类故障：断网、模型缺失、用户取消。已有复现优先于扩建一套大平台。录音来源需授权，公共可分发语料与私人 fixture 分开保存；合成语音只算补充材料。

候选晋级阈值（待基线确认的工作假设，非当前成绩）：预先选定一项主收益，其余作为不劣化约束，不能事后挑最好的指标。在预先选定的主指标上达到用户可感知收益，例如修正耗时降低约 20%，且关键错误不回归、首音或打断 p95 不劣化超过约 10%。样本太少时只报告原始分布，不用漂亮百分比下结论。对声学误打断需同时报告每小时误触次数和真打断漏检，不能只报一种。

内存/CPU、实时率、包体/模型体积、下载成功、许可证、费用与数据去向为硬约束。用户未批准的数据外发、收费和额外持久化不能用收益加权抵消。

## 7. 分阶段交付路线

投入窗口按一名维护者与可用测试设备估算，不是发布日期承诺。每次一个原子单元；发现明确丢句/误发等高损失缺陷可插队修复，不等完整评测设施建好。

| 阶段 | 交付及最小实验 | 退出门槛 | 发布/回滚与责任 |
| --- | --- | --- | --- |
| R0 已知缺陷闭环，立即 | 完成 Kokoro 两种精度及支持文件补修；盘点已发现问题；同步源码、产物、测试、变更记录 | 回归先红后绿；冷下载、有效缓存、旧坏分片分别验证，真实/模拟证据分开；CI+安装通过；未验证项写清 | 维护者合并；发布前形成具体补丁版本与清单；不覆盖旧 tag，问题用反向提交或后续补丁 |
| R1 最小真实闭环，首个 1–2 周窗口 | 真实 ASR→可编辑草稿→按设置发送→TTS；先覆盖现有默认资产及三类故障 | 有可重复命令与少量真实任务结果；错误可定位、草稿可找回；不以模拟 E2E 放行硬件项 | 维护者持有台架，测试者提供设备结果；先开发版/自愿测试再扩大；已就绪时回现有引擎；否则保留草稿、手工发送/纯文本，不强迫下载 |
| R2 最高损失体验，与 R1 交替，后续 2–4 周窗口 | 只处理实测中最伤任务成功的一个问题：编辑冲突、误发、迟到定稿或失败恢复；必要时原文/改写一键撤回 | 用户原文与手改不丢；不会静默重发；修正成本或任务成功率实际改善 | 默认行为变化须显式说明；保留旧模式；同一存活会话内保留文本，主动结束时清理，不新增默认录音库 |
| R3 更新与退路，同期按风险分小单元 | 默认模型资产不可变清单与辅助目录摘要；上游新版本只进入候选；TTS 回退先做已缓存本地候选 PoC | 冷安装/缓存命中/旧坏分片/目录缺失/断网/镜像/取消通过；失败不自动启用云或收费 | 维护者核验来源与许可，批准资产变更；旧清单可回滚，缓存不静默破坏；没有合适后端可零新增 |
| R4 有证据的单瓶颈改进，约 4–8 周候选窗口 | 分开评估新 ASR、轮次检测、传输层，最多推进其中一个实验 | 同任务同硬件击败基线；无收益则归档，不改默认值 | 实验配置隔离；停止实验即可回原路径；原生包、音色编号、词典、产物与许可一起验证 |
| R5 产品增强，约 8–12 周以后候选 | 有用户需求时在“播放中提问、选段朗读、会话摘要”中只选一项 | 明确使用者与任务；核心指标已稳定；试用实际减少操作或返工 | 实验默认关闭，不引入新的隐私/收费默认值；两个验证回合无稳定收益即停止 |

每阶段的发布定义包含：源代码与产物一致、所有必需检查成功、与用户任务相关的真实验证、安装形态、变更说明、回滚路径；合并不等于发布，发布不等于目录上线。外部依赖缺失时只推进独立项，依赖项保持未验收。

## 8. 持续更新：不追着每一次模型新闻改默认值

- 日常：复用现有 Edge 实时探针与宿主版本检查；信号失败先区分服务故障、配额、协议、网络与代码，不因一次共享 IP 限流自动切服务。
- 每月一次有时间上限的候选复核：只看官方 release、模型卡、运行时兼容、许可变化与真实用户需求。月度复核不等于每月必须升级。
- 新候选统一记录：来源、immutable revision、完整资产、运行时/ABI、语言与音色、许可、硬件、成本、数据去向、取消语义、测试结果和回退；先用现有文档/脚本记录，不先建设控制台。
- 分离“上游有新文件”“下载来源漂移”“已批准升级”。摘要不匹配永远不能自动接受新摘要。下载清单锁版本，更新审批才改变版本。
- 回退原则：先止住在途旧请求，再只对尚未播放的内容做一次选择；已播放片段不重复，用户打断后不重试。未预下载的本地模型不能被承诺为即时退路。
- 重试 TTS、切换 ASR 或恢复连接不得因此重新发送宿主 prompt；停止朗读不自动取消宿主开发任务。已受理的云请求即使本地取消也可能仍收费，费用 PoC 要实测这一边界。
- 退回旧引擎也要检查资产与 ABI 就绪；不可用时保留草稿并转手工发送/纯文本，不能强迫下载或外发。
- 先交付可操作的错误与手动选择，再决定自动切换；自动回退只可在用户事先授权的数据/费用边界内运行。纯本地用户绝不因故障自动上传。
- 运行时升级按原生包、模型、词典、音色索引、产物、许可、缓存及回滚完整评审；接口类型能通过不是迁移完成。
- 主维护者负责发布和默认值，贡献者提供可复现证据，设备验证者维护真实测试结果。无人能够持续维护的后端不进入默认支持。

## 9. 对抗性审查与取舍

### Blocker

- 不能只修 int8 后宣布模型更新问题已关闭。已补查 fp32 和中文词典；辅助目录摘要、fp32 真实推理仍需分别验收。
- 基准本身不等于用户价值；缺少真实 ASR 与麦克风闭环时，不能承诺自然全双工可靠。
- 免费调用不提供默认收费或数据外发授权；任何路线若依赖这一跳必须先改变方案。

### Important

- “先把基础设施做全”会再次陷入无限治理。R1 收窄为一条真实闭环与三类故障；已复现的用户损失随时优先修复。
- 模型更新频繁不意味着本项目需要频繁更换模型。不可变资产与候选晋级分离，维持现状是合法结论。
- 流式、定稿、端点、LLM 和播放器是不同瓶颈；不同时更换三层来追求一次演示提速。
- WebSocket 的连接内有序不能消除异步任务、取消与重连的旧响应；沿用当前生命周期语义，除非行为测试证明可删。
- 多后端可能扩大失败面；先有授权、预备就绪与去重的退路，再谈自动回退。
- 原文可恢复不等于无限存储。默认只承诺同一存活会话内断线恢复，主动结束按策略清理；关页、进程崩溃及跨重启恢复不是同一保证，持久化录音/转写必须单独获得授权并确定期限、加密与删除规则。

### Minor

- 首轮只用五个主指标；数值是决策工具，不为了好看加指标或徽章。
- 不把竞品界面和功能数量当需求；长文的摘要卡、双主持或语音皮肤没有任务证据就不排进近期。
- 路线估时依赖设备与人员，按阶段退出条件推进，不按日期强行上线。

### Open Questions

- 目标平台优先顺序和可持续提供的硬件是什么？本轮不扩大当前兼容承诺。
- 实际用户最常进行长文本听写、开发指令还是免手对话？下一轮用任务成功与修正成本验证。
- 正式云服务是否有真实使用者愿意配置密钥并接受费用？没有则不实现。
- 语义端点/客户端 VAD 是否值得增加模型或算力？只有分解后的延迟与错误数据能回答。

### Verdict

只读独立审查已复核路线图与相关传输 ADR；取消、恢复、费用、回滚及误导论证修正后，无残留 Important 或 Blocker。此结论仅覆盖文档与方案，不是模型、硬件或性能验收。

优先顺序为“已知缺陷 → 一条真实闭环 → 最伤用户的体验问题 → 可控更新与退路 → 按瓶颈择优实验”。没有依据将新模型、多后端或传输重写设为近期必做。旧 ADR 的 accepted/deferred 状态保持；本文不替用户批准产品方向或协议迁移。
