## 0.1 一句话结论

**dsh-voice-mode 当前最强的资产是"声学前端 + 实时打断工程化"（ADR-0001/0003/0004/0006 全套），与头部产品（ChatGPT Voice / Gemini Live / Grok Voice）齐平甚至局部领先；最弱的两块是人格/情绪维度（SoTA 全文级 S2S 模型均已支持，dsh 仍仅 `spokenFormat` 文案层），与端到端 sub-200ms TTS 首包（Cocosue 150ms / Cartesia 90ms / Fish 70ms 均超越）。借鉴优先级最高的三档如下：**

**1) 立即可补的小工程量（≤3 天，本地 0 风险）：**
1. **内联情感/非语言标签 DSL**（`<laugh>`、`<whisper>` 等） → tts-local 文本归一化 → 分引擎映射：Edge → `mstts:express-as`、Kokoro → SSML phoneme、VITS → 停顿+emoji（ElevenLabs v3 / Orpheus / Bark / Dia 共识）
2. **截短长静音后自动触发"3 条要点摘要"** → `/voice-mode/recap` 路由 + `client.tsx` 折叠面板（Otter / Fireflies / Granola / NotebookLM 共识）
3. **字幕 `[S1]/[S2]` 说话人标签** + pyannote-audio ONNX pipeline（pyannote 4.x 提供单一 ONNX 解码；放在 `asr-host.ts` finalize 路径 + 单说话人跳过快路径）
4. **设置项 `interruptThreshold_ms` + `turn_detection.eagerness` 暴露**（CONTEXT.md L46-49 仅有 `interruptLevel/silenceMs/echoGateDb` 三键，命名与 Vapi/Retell 缺对齐；**保留旧键 + 新增数值键 + alias 文档化**，避免破坏既有 dsh 用户配置）

**2) 中等工程量（1-2 周，本地+小改）：**
6. **声音克隆（5–30s 参考音色）** → OpenVoice v2 的 tone-color decoder 接 Kokoro（MIT 商用 OK）
7. **xAI `/v1/realtime` WebSocket 引擎作为云端 fallback**（比 OpenAI Realtime 便宜 10×：5min ≈ $0.25 vs $2.88；支持 `/v1/custom-voices` ≤120s 克隆；与本仓 ASR/TTS 三方独立选型理念兼容）
8. **WebRTC APM3 (webrtc-audio-processing) 替代自研 NLMS**（ADR-0001 "原生 AEC 失效时"分支；带 RES 的 AEC3 + ERLE 实测基线来自 ADR-0005）
9. **ADR-0004 协议骨架直接抄三家共识**：单一 WS + binary int16 上行 + JSON 事件下行 + producer seq/ts（OpenAI Realtime / Gemini Live / Pipecat 三家一致）

**3) 大工程量 / 战略级（1-3 月）：**
10. **会话式语音人格层 + 情绪识别** → Hume EVI emotion scores 注 system prompt；本地 emotion2vec 兜底；TTS 接 Azure Dragon HD Omni 参数化情感 / ElevenLabs Audio Tags（情绪与拟人度的代际差）
11. **TTS 流式首包压到 ≤200ms** → 替换 Edge 为 Cartesia Sonic Stream WebSocket（90ms TTFA）；音频流片段级 chunked；预期体验"对答不卡顿"
12. **DTLN / NKF-AEC + WebRTC APM3 后置链**（双讲场景下用 sample 级 DNN-AEC，再接 APM3 = ERLE 期望 +10dB）

**两条被夸大的"借鉴点"已被反证：**
- ❌ "用 WebRTC 整体替换 WebSocket" — 行业 0/7 用 WebRTC 全栈做实时双向；引入 SFU/STUN 改造 host 端成本远大于 ADR-0004 WebSocket 提案。
- ❌ "上 OpenAI gpt-realtime 一键换代" — 5 分钟对话 ≈ $2.88，且需 ephemeral token + WebRTC 才能浏览器侧直连；与本仓"零 API Key、识别本地"的核心卖点冲突，**不应**直接替代 STT/LLM/TTS，**只**作为特殊多媒体输入场景（视觉/多模态）的辅助 fallback。

## 0.1b 对抗性审查总结（2026-09 第二轮收敛）

> 5 份子代理报告 + 主会话独立验证 + 对抗性审查三轮收敛后，**最终保留 36 → 32 条借鉴项**；移除/冻结 7 条 Blocker 项（含 C6 与 D2 自反证冲突、Krisp VIVA 闭源专利、pyannote VAD 旁路缺基线、Cartesia 破坏零 API Key、Audio Overview 超出插件范畴、A8 已具备归类错）。

**审查 Pass 比例**：26 / 36 = **72%**。**Blk 比例**：7 / 36 = **19%**。

**最关键修正**（第三轮收敛）：
1. **A5 命名分歧**：Vapi/Retell 用 `interrupt_threshold_ms`，本仓用 `interruptLevel` 三档——保留旧键以保 schema 兼容 + 新增数值键。
2. **A8 错类**：录制开关 `fixture-recorder.ts` 398 行实体已存在且 `localStorage` UI 已部分可配，不应放在"借鉴 A 组"，降级到 backlog。
3. **A4 Krisp VIVA Blk**：VIVA 闭源专利，无开源对照，半年内无法落地真实 benchmark，本期不立项。
4. **C6 与 D2 自反证冲突**：scan 文件内部"小优先级"违反自家红线。已从 C 数组移除。

## 0.2 第一性原理断点：对话式语音真正难在哪

> 综合 5 份子代理报告 + 主会话独立验证。

**声学层（AEC / VAD / 唤醒 / 降噪）是被多家共识"已解决"的领域。**
- WebRTC APM3、Silero v5、TEN-VAD、Picovoice Cobra、speexdsp、WebRTC APM + RNNoise 后置链均是公开/可下载 SOTA，**不构成壁垒**。本插件在 ADR-0001/0006 上（原生 AEC + 峰值保持门控 + 三档 confirmFrames）已经做得接近头部。

**真正的难处是"社会-语用层"**——发言权调度：
- **轮次让位（turn-taking）**：识别对方是真打断还是"嗯/对/那么"，是工业界共识（OpenAI Realtime `turn_detection`、Deepgram Flux `eot_threshold`、Cartesia Voice Agent、LiveKit Multilingual Turn Detector 都显式建模）。本插件 VAD 阈值 0.35（段间）/ 0.5（端点）是能量门，对"语义级让位"无能为力。
- **人格一致性**：Sesame CSM、Cartesia Sonic Voice Design、ElevenLabs Voice Library、Hume EVI 自定义声纹均为"人格层"工程。本插件仅靠 `spokenFormat` 文案层。
- **延迟与人性的张力**：所有头部厂商延迟预算在 200-900ms（P50），sub-second 是基本门槛。本插件当前 `tts-queue` 是完整句合成 + base64 SSE，首包约 600-800ms，离 Cartesia Sonic 90ms / OpenAI Realtime 280ms 有明显距离。
- **系统级集成**：Apple Intelligence 的"读消息/看日历"、Google Gemini Live 的"视觉共指"、Copilot+Recall 的"屏幕记忆"——Web 平台物理边界决定本插件永远补不齐这些；做选择必须接受 Web 边界。

**dsh 最薄弱的一格：**
- 拟人度（人格 + 情绪 + 非语言发声 + 多角色对话）四项基本空白——单独补每一项都只需 1-3 周，集齐才让用户感到"在和人说话"。
- TTS 流式首包慢（~600ms）——对话节奏的瓶颈，比"打断灵敏度"更影响"像说话"。
- 跨语言/英文国际用户场景弱——Wispr Flow / ElevenLabs Conversational 已支持 100+ 语种。

## 0.5 红线（被夸大的借鉴点被反证）

### R1. "WebRTC 全栈 vs WebSocket" 不可行
- 行业 7/7（OpenAI / Pipecat / LiveKit / Gemini / Anthropic / xAI / MiniMax）全部选 WebSocket 或 WebRTC 作实时双向通道；其中只有 LiveKit（自带 SFU）/ Agora/Daily 才用 WebRTC 全栈。
- 本插件"浏览器→自 host→LLM"拓扑不兼容 SFU 模式；引入 SFU = 整套服务端重写。
- **决定**：仍走 ADR-0004 WebSocket 路线；不引入 SFU；用 WebRTC AudioProcessing 库（不带 SFU）做声学部分，避开基础设施改造。

### R2. "OpenAI Realtime 一键换代" 不应做
- 成本：5 分钟 ≈ $2.88（输入 $32 / 1M + 输出 $64 / 1M audio tokens），比 Edge 默认便宜方案（¥0.3-0.5/5 分钟）贵 ~40×。
- 浏览器侧必须走 WebRTC + ephemeral token = 引入 OpenAI API Key 依赖，破坏"零 API Key"卖点。
- 与本仓"STT/LLM/TTS 三方独立选型"理念反向 —— OpenAI 是 all-in-one 绑模型。
- **决定**：保留 STT/LLM/TTS 三方独立选型；OpenAI Realtime 不替代主链路；仅当用户开启"视觉/多模态"高级功能（需要 OpenAI Key）作为可选增强模式（默认关，与显式 opt-in 弹窗配合）。

### R3. "PlayHT / LMNT" 已停运
- PlayHT (PlayAI)：Meta 于 2025-07 acqui-hire 团队；API 自 2025-07-26 离线；play.ht 现展示"We have shut down the service"。
- LMNT：lmnt.com 与 docs.lmnt.com 仅展示"Our speech generation journey has come to an end"。
- **决定**：将两者列为历史参考；TTS 默认 fallback 已无此选项。

### R4. "Moshi / GLM-4-Voice / Step-Audio2 S2S 一键集成" 与本仓定位冲突
- 三者都需要 4GB+ 显存；本插件定位"开箱即用 + 零配置"，目标用户群体没 GPU。
- Sesame CSM 双卡 A100 / H100，本仓无法直接部署。
- **决定**：仅作"未来可选插件"路线（用户显式 opt-in + 自托管权重）；不为短期借鉴点。

### R5. "用 Hume EVI 取代 LLM" — 误解
- Hume EVI 是情绪识别 + expressive TTS + 任意 LLM 的"接口层"，**不**取代 LLM。它是给 LLM 加 emotion scores 输入，与 LLM 并行。
- **决定**：情绪识别可作旁路插件接入，LLM 仍是 DSH 内核。
