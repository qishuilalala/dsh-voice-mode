# L4 常驻回归：真实 LLM 回复 → 朗读闭环

> 状态：**自动化子集已闭环**（2026-11-27 首次通过）。本文说明它覆盖什么、怎么跑、最近一次证据，以及它**不**覆盖什么。

## 为什么有它

L4（真实 LLM 生成 → 语音播报）长期是「未闭环」项：此前只能人工试一次，没有可重复证据。人工试过不等于回归可控——模型、引擎、密钥、提示词任一变化都可能静默破坏这条链路。

现在把它变成一条命令：`npm run verify:l4`（脚本 `test/l4-real-llm.mjs`）。

## 覆盖什么

| 环节 | 断言 |
|---|---|
| 真实 LLM | 调用真实 LLM 通道拿回复，非空、≤ 预算延迟（60s） |
| 真实朗读引擎 | 把**上一步的回复原文**交给 MiMo 引擎合成（与生产同一份 `src/tts-mimo.ts`） |
| 音频可用性 | 字节数 > 5KB、MIME 为容器格式（`audio/wav` / `audio/mpeg`）、延迟 ≤ 30s |
| 凭据安全 | 自检输出流中不含任何凭据原文 |

## 凭据解析（永不落盘、永不打印）

- **MiMo**：`DSHVM_MIMO_API_KEY` → `MIMO_API_KEY` → **运行中 dsh 进程环境**（`/proc/<pid>/environ`，需 root）→ 主机配置字面量。
  - 注意：主机配置里的 `mimoTts.apiKey` 常写成 `!!js process.env.MIMO_API_KEY`，那是**表达式不是密钥**，脚本会识别并跳过（早期误把表达式当密钥发出去会导致 `Invalid API Key`）。
- **LLM**：`DSHVM_LLM_BASE_URL` + `DSHVM_LLM_API_KEY` + `DSHVM_LLM_MODEL` → 否则按 `OPENROUTER_API_KEY` → `DEEPSEEK_API_KEY` 顺序尝试，记录实际生效通道。

## 跳过语义

缺凭据时打印 `SKIP` 并 exit 0——CI 无密钥不应判红，但**跳过不是通过**，输出明确区分。要真正跑，需要至少一条可用 LLM 通道 + MiMo 密钥。

## 最近一次证据（2026-11-27）

```
LLM 通道=openrouter 模型=deepseek/deepseek-chat-v3.1  回复 26 字 / 1143ms
MiMo 合成 215084 字节 / 3030ms  mime=audio/wav
密钥不外泄 ✓
```

## 不覆盖什么（不许混淆）

- **不碰麦克风**：收音、回声消除、打断、唤醒词都不在本脚本内，仍由[真机四项必过](must-verify-manually.md)覆盖。
- **不测播放**：只验证「音频字节生成」，不验证扬声器实际出声与听感。
- **不测前端链路**：不经过浏览器播放队列与字幕，只覆盖「回复文本 → 音频」这一段。
- 因此 L4 自动化通过 **不能**替代真机验收，两者是互补关系。

## 维护

- 脚本随仓库测试清单进入 CI（无密钥时跳过），保证不腐化。
- 若上游改了 MiMo 的接口形状或默认模型，本脚本会以真实失败暴露，而不是静默降级。
