# ADR-0006：打断模式自动探测降级，不要求用户理解声学参数

- 状态：**已接受**（2026-08-30 拍板）
- 日期：2026-08-30
- 决策人：用户（回答「第一用户是外放的桌面用户，还是戴耳机的开发者」= **都是**）
- 前置：[ADR-0001](0001-native-aec-primary.md)（物理边界）、[ADR-0005](0005-acoustic-regression-harness.md)（ERLE 采集）

## 背景

用户明确：**外放的桌面用户与戴耳机的开发者同为第一用户**。这条回答否掉了一个隐含的省事方案——"默认按耳机场景调，外放的人自己去改设置"。

当前的现实是：

| 设置项 | 默认 | 用户要理解什么才能用对 |
|---|---|---|
| `bargeInMode` | `auto` | 自己判断本机外放能不能撑住自动打断 |
| `echoGateDb` | 6 | **分贝**，以及"打不断降 3-4、噪音误打断升 8-10" |
| `interruptLevel` | 0 | 确认帧数，且 0 是高门槛（数值越大越灵敏，反直觉） |

README 的排障表实际上是在教用户调声学参数。对"外放的桌面用户"这个第一用户群，这是不成立的——**他们遇到的第一个现象是"AI 说几个字就被自己打断"，而不是"我该把 echoGateDb 调到几"。**

同时，ADR-0001 已经确立了物理边界：残差回声 ≥ 用户语音时，信号级方法不可分。也就是说，**有一部分设备/环境组合，`auto` 在物理上就不该被启用**。现在的问题不是"能不能消得更干净"，而是"系统自己知不知道这台机器不该用 auto"。

## 决策

**打断模式由系统探测决定，用户不需要理解声学参数。**

### 1. `bargeInMode` 增加第三个取值，并成为新默认

| 取值 | 语义 |
|---|---|
| `detect`（**新默认**） | 系统探测本机声学条件，自动在 auto / manual 之间选择，并在状态条说明原因 |
| `auto` | 强制自动打断（用户明确要，不管探测结果） |
| `manual` | 强制长按打断 |

保留 `auto` / `manual` 是为了不夺走已经调好的用户的控制权；把 `detect` 设为默认是为了让**没调过的用户开箱即对**。

### 2. 两级探测

**第一级 —— 零成本，进入语音模式即可判定**

`getUserMedia` 后读 `track.getSettings().echoCancellation`（现有代码已有此信号，`src/asr.ts` `startRecorder` → `config.onAecState` → `src/client.tsx:1457` `bus.setEchoBypass`）。

- `=== false` → 原生 AEC 未生效（耳机无原生 AEC / Safari VoiceProcessingIO 失效）→ **直接判定不具备 auto 条件**，落 `manual`，状态条提示「本机回声消除未生效，已切为长按打断」

这一级不需要任何新的信号采集，是纯粹的"把已有信息用起来"。

**第二级 —— 首句朗读前 ~2s 的探测窗口**

原生 AEC 生效不代表效果够用（大音量外放、蓝牙音箱、劣质扬声器的非线性失真都会让残差抬高）。需要实测。

**关键复用**：现有 `aboveEchoFloor` 在 `echoFloorRms === 0` 时保守拒绝打断（`src/asr.ts`，注释明确"代价是首播前 ~2s 无法自动打断"）。**这个本来就存在的盲窗，正好是探测窗口**——不额外牺牲任何体验。

窗口内采集：
- `echoFloorRms` 收敛后的绝对水平 —— **可用，但需带置信度**。
  > 更正记录：2026-09-02 早些时候我据合成基准把这一项判为作废（称其低估回声 28–57 dB）。
  > **真机数据推翻了该否决**：实测误差只有 0.1 dB（纯听）/ 2.8 dB（打断场景），是可用的估计量。
  > 但误差随棘轮活跃度上升，所以必须同时读 `doubleTalk` 触发率作为置信度——触发率高时地板不可信，
  > 退回用播放期残差中位数。见 [findings](../findings/2026-09-02-echo-gate-ratchet.md)。
- 播放期残差 RMS 的**中位数**（地板不可信时的退路）
- ERLE（定义见 [ADR-0005](0005-acoustic-regression-harness.md)）

判据（阈值由 ADR-0005 的基准标定，**不在本 ADR 里拍脑袋定死**）：
- 回声地板高于阈值 / ERLE 低于阈值 → 运行中降级 `manual`，状态条提示「本机外放回声较强，已切为长按打断」
- 否则保持 `auto`

### 3. 硬约束：降级必须发生在第一次自打断之前

这条是本 ADR 的**验收标准**。如果探测要等到用户已经被自打断一次才生效，那么对第一用户来说这个功能等于不存在。

因此第二级探测的判定必须在首句朗读的探测窗口内完成，而不是"统计几次误打断后再降级"。

### 4. `echoGateDb` 降级为高级选项

不删（已有用户可能调过），但：
- 从设置面板的常规区移到高级/折叠区
- 描述改为"仅在 `bargeInMode=auto` 强制模式下生效；默认的 `detect` 模式自动标定"
- README 排障表不再把"调 `echoGateDb`"作为首选建议，改为"确认打断模式显示为自动还是长按"

> **2026-09-02 真机确认**：这个旋钮在当前主流路径上确实是空操作，但原因与我最初推断的不同。
> 真机 3.1 分钟朗读期里 Silero **0/777 帧**把回声判成语音 ⇒ 打断的前置条件从未成立 ⇒
> 回声门控这段代码**从未被执行**，`echoGateDb` 自然不起作用。
> 因此 README 排障表那一行**要改掉**（它在教用户调一个走不到的阈值），措辞是
> "打不断的原因在 VAD 灵敏度或确认延迟，不在这个阈值"。

## 后果

**正面**
- 外放用户开箱可用：要么自动打断真的能用，要么明确落到 100% 可靠的长按打断，**不会落到"自打断"这个最差状态**
- 耳机用户不受影响：第一级探测在耳机 + 原生 AEC 生效时直接放行 `auto`
- 把 ADR-0001 承认的物理边界，从"文档里的一句话"变成"系统的运行时行为"
- 声学参数从"用户必须理解"变成"系统自己标定"——这是 §2.3 I5 之外，唯一一条同时改善两类第一用户的改动

**负面 / 成本**
- 依赖 ERLE 采集，而 ERLE 目前不采集 → **必须等 ADR-0005 的基准先给出 ERLE 的定义与标定数据**，否则第二级探测的阈值就是又一个拍脑袋的魔数（那样等于没解决问题）
- 第一级可以先独立上线（零依赖，收益立刻可见）；第二级必须等标定
- 运行中降级会造成"说好的自动打断突然变成长按"的体感突变，状态条提示必须写清楚原因，否则用户以为坏了
- 新增一个设置取值，需要迁移已有配置（`auto` 保持 `auto` 不动，新用户默认 `detect`）——**不能把老用户的 `auto` 静默改成 `detect`**

## 依据

- 用户明确回答"都是第一用户"，排除了"为单一场景优化"的选项
- ADR-0001 的物理边界意味着 `auto` 存在必然失效的设备组合，系统必须能识别它们
- 现有代码已经有第一级探测所需的全部信号（`getSettings().echoCancellation`），只是拿去做了 AEC 旁路决策，没拿去做打断模式决策——**信息已经在手上，只是没用**
- 探测窗口与现有的"首播前 2s 盲窗"重合，零额外体验成本

## 落地顺序

1. **第一级探测**（可立即做，零依赖）：`echoCancellation === false` → 自动落 `manual` + 状态条提示
2. **ADR-0005 基准就位** → 标定 ERLE 与回声地板的降级阈值
3. **第二级探测**：用标定出的阈值做运行时降级
4. **设置面板与 README 调整**：`echoGateDb` 移入高级区，排障表改写

## 备选方案

- **A：保持现状，靠 README 教用户调参**——被用户的"都是第一用户"直接否掉
- **B：默认改成 `manual`，想要 auto 的自己开**——对耳机用户是明显的体验倒退（他们的 `auto` 本来就能用），把问题从一类用户转移到另一类，不解决
- **C：不加 `detect` 取值，直接让 `auto` 内部自动降级**——实现更省事，但语义混乱："我明明设了 auto，为什么是长按？" 三值方案让"我要的"和"系统判断的"可区分
