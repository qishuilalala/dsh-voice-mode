# ADR-0004：建立离线声学回归基准，把手调常数变成有守卫的参数

- 状态：**已接受**（2026-08-30 拍板，优先级最高）
- 日期：2026-08-30
- 决策人：用户（回答「愿意为回归基准付一次性成本吗」= 行）

## 背景

打断链的行为由至少 12 个手调常数决定：

| 常数 | 值 | 位置 |
|---|---|---|
| `echoGateDb` | 6 dB | 设置默认 |
| 检测 VAD 阈值 | 0.35 | `src/asr-host.ts:330` |
| 端点 VAD 阈值 | 0.5 | `src/asr-host.ts:294` |
| `INT_CONFIRM_FRAMES` | 3 / 2 / 1 | `src/client.tsx:32` |
| `peakDecay` 基数 | 0.9 per 64ms | `src/asr.ts:578` |
| `floorAlpha` 基数 | 0.98 per 64ms | `src/asr.ts:579` |
| `SPEECH_RMS` | 0.015 | `src/asr.ts:107` |
| `VAD_CONTINUE_RMS` | 0.02 | `src/asr-host.ts:149` |
| `MIN_SPEECH_MS` | 250 | `src/asr.ts:112` |
| 确认窗口 | 800 / 350 / 400ms | `src/asr-host.ts:151-154` |
| delay 置信门 | peak > 0.5 | `src/client.tsx:708` |
| 迟滞衰减 | 连续 2 拍假才减 1 | `src/client.tsx:1426-1428` |

每一个都是真机试错的产物，git log 里能看到它们被反复调整（如 2a67df7「迟滞降 confirmMs 566~2796→~500ms」）。

**问题：它们的正确性没有任何一行代码保护。** 现有 `test/aec.test.mjs` 测的是 NLMS 的数值行为（收敛、发散防护、互相关峰值），不是端到端的门控决策。ADR-0001 的诊断证据（"resid 从 0.11 降到 0.0017~0.0255"）是一次性口头记录，没有 fixture。

结论：**今天任何人改动 `peakDecay` 或 VAD 阈值，CI 全绿，自打断可能已经回来了。** 而这个 bug 的用户可见形式是"AI 说几个字就被自己打断"——最严重的体验故障。

## 决策

建立**离线声学回归基准**：固定音频 fixture + 确定性重放 + 指标门。

### 0. 覆盖边界（2026-09-02 修正，此前有夸大）

初稿隐含了"12 个常数全部获得守卫"。**不成立**——常数分布在两侧，一次客户端抽取吃不到 host 侧的：

| 常数 | 位置 | 客户端纯核可覆盖 |
|---|---|---|
| `echoGateDb` 6 | 设置默认 | ✅ |
| `peakDecay` 0.9 | `src/asr.ts:578` | ✅ |
| `floorAlpha` 0.98 | `src/asr.ts:579` | ✅ |
| `confirmFrames` 3/2/1 | `src/client.tsx:32` | ✅ |
| 迟滞连续 2 拍 | `src/client.tsx:1426-1428` | ✅ |
| `SPEECH_RMS` 0.015 | `src/asr.ts:107` | ⏳ 阶段二（分段级联） |
| `MIN_SPEECH_MS` 250 | `src/asr.ts:112` | ⏳ 阶段二 |
| delay 置信门 0.5 | `src/client.tsx:708` | ⚠️ 仅间接（经 `playingTailUntil` 影响播放态） |
| 检测 VAD 0.35 | `src/asr-host.ts:330` | ❌ host 侧，需独立重放脚本 |
| 端点 VAD 0.5 | `src/asr-host.ts:294` | ❌ |
| `VAD_CONTINUE_RMS` 0.02 | `src/asr-host.ts:149` | ❌ |
| 确认窗口 800/350/400 | `src/asr-host.ts:151-154` | ❌ |

即：**第一批覆盖 5 个，阶段二 +2，host 侧 4 个需要另一条重放路径**（依赖 `sherpa-onnx` + 模型下载）。
不要在任何地方宣称"12 个常数全有守卫"。

### 0.5 分层：合成先行，录音后补

`test/aec.test.mjs` 已有确定性合成信号的先例。据此分两批：

| 批次 | 依赖 | 守什么 |
|---|---|---|
| **第一批** | 无（不需 npm install / 模型 / 录音 / 联网） | 判定层逻辑回归。已落地：`scripts/bench-echo-gate.mjs` |
| **第二批** | 真机录音 | 真实声学：扬声器非线性、原生 AEC 的 RES 残留特征、蓝牙时基抖动、清辅音 |

**合成信号不能用于 VAD 层 fixture**——调研实测显示，逐段叠加的微小噪声差异即可让 Silero 完全漏检某段（`threshold=0.35` 与 `0.5` 下分段结果差异显著）。VAD 层必须用真机录音。

### 0.9 第一批的产出（已完成）

`node scripts/bench-echo-gate.mjs`——零依赖，报告模式。

**它在建成的当天就抓到了一个缺陷**：回声地板因 `doubleTalk` 冻结而成为单向棘轮，导致回声门控在真实回声下判别余量≈0.4pt，且 `echoGateDb` 在文档建议范围内完全无效。
详见 [findings/2026-09-02-echo-gate-ratchet.md](../findings/2026-09-02-echo-gate-ratchet.md)。

这条本身就是本 ADR 的投资回报证明：**基准还没建完就付清了成本。**

### 1. Fixture 集（一次性录制，入库或用 Git LFS）

按「设备 × 环境 × 场景」交叉，每格 3–5 条，16k 单声道 WAV：

| 维度 | 取值 |
|---|---|
| 设备 | 笔记本外放（原生 AEC 生效）｜耳机｜外放 + 原生 AEC 失效（模拟：录制未经 AEC 的原始麦克风） |
| 环境 | 安静（<35 dBA）｜有底噪（风扇/空调）｜人声背景 |
| 场景 | 纯 TTS 回声（不应打断）｜TTS + 用户开口（应打断）｜纯用户语音（不应误开段）｜双讲重叠 |

每条 fixture 附一个 `.json` 标注：`{ playing: [起止], userSpeech: [起止], expectInterrupt: true/false }`。

**录制同时保存 TTS 参考轨**——这是 AEC/门控重放的必要输入，缺了整个基准就废了。

### 2. 重放器

把 `handleAudio` 的判定链（AEC → RMS → echoPeak/echoFloor → aboveEchoFloor → VAD → confirmFrames）抽成**纯函数管线**（当前它已经基本是纯的，只是嵌在 `asr.ts` 的闭包里），喂 fixture 帧，输出决策时间线。

VAD 部分在 Node 侧用同一个 sherpa-onnx Silero 实例——保证与线上同模型同阈值。

### 3. 指标门（进 CI）

| 指标 | 定义 | 建议门槛（首轮先采基线，再定门） |
|---|---|---|
| 误打断率 | `expectInterrupt=false` 的 fixture 中触发打断的比例 | 0%（外放 + 原生 AEC 生效格） |
| 漏打断率 | `expectInterrupt=true` 中 1.5s 内未触发的比例 | < 5% |
| 打断确认延迟 | 用户开口 → 触发，P50 / P95 | P50 记录，P95 不回退 |
| 误开段率 | 纯噪声 fixture 上 `speechActive` 置真的比例 | 记录基线 |
| ERLE | 自研 AEC 路径的回声抑制比（dB） | 记录基线（ADR-0001 遗留项依赖它） |

CI 策略：**先只报告不拦截**（跑够 2 周建立信心），再改为"P95 回退 >20% 即失败"。

## 预期后果

**正面**
- 12 个魔数从"不敢碰"变成"可以改，改坏了 CI 会说"
- [ADR-0002](0002-client-side-vad.md)（VAD 下沉）和 [ADR-0003](0003-realtime-transport.md)（换传输）才具备"证明行为等价"的手段——**没有本 ADR，那两个都是裸奔**
- ADR-0001 遗留的"自研 AEC 未根治"有了收敛判据（ERLE 数字），可以决定是修还是降级（评审 §2.2 S4）
- 参数调优从"真机试 + 主观体感"变成"跑一次脚本看表"，迭代速度数量级提升

**负面 / 成本**
- 一次性录制 + 标注：约 2–3 天（含在多种设备上录）
- 仓库体积：30 分钟 16k 单声道 WAV ≈ 57MB。建议 **Git LFS 或独立 fixture 仓库**，不要直接塞进主仓
- fixture 不覆盖的设备/环境仍会翻车——基准是防回归的，不是防新场景的。必须明确这条边界，否则会产生"CI 绿了就没问题"的错觉
- 判定链抽纯函数需要小规模重构 `asr.ts`

## 依据

- 本项目的历史 bug 分布（git log）显示：绝大多数严重故障是**声学判定回归**，而非功能缺失。防回归的投入产出比高于加功能
- 判定链已经接近纯函数（`aec.ts` 顶部注释明确"纯模块，可单测"），抽离成本低
- 现有 `scripts/bench-asr.mjs`（289 行）证明项目已有离线评测的工程习惯，本 ADR 是同一模式在声学层的延伸

## 备选方案

- **A：合成 fixture 替代真机录制**（用 TTS 生成回声 + 加混响 + 加噪）——成本低得多，但合成回声的非线性特征（扬声器失真、AGC、编解码）与真机差距大，对 AEC 类问题基本无效。**可以作为补充，不能作为替代**
- **B：只做端到端真机冒烟测试**（每次发版手动跑一遍清单）——现状就接近这个，问题是不可重复、不可量化、依赖某一台机器
- **C：不做**——继续手调 + 真机验证。可接受的前提是：不再做任何声学层改动。但 ADR-0002/0003 都要动这一层，所以这个前提不成立
